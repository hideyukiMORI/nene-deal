## First production install — and the incident it surfaced (#78 / PR #79)

hide installed Deal on HETEML (`https://deal.ayane.co.jp` — health OK, DB OK,
`/demo/standard` live). Post-install inspection found two things:

1. **`install.php` was still reachable (HTTP 200).** Timeline from the server:
   install completed 18:41 (marker written, self-delete worked), then a full
   artifact re-rsync at 19:36 restored `install.php`. Deleted it over SSH;
   `/install.php` now falls through to the SPA like vault. **Operational
   note: every future full-tree rsync resurrects the installer — delete it
   after deploys, or exclude it from update rsyncs.**
2. **The blocked response was a 200 with PHP warnings leaking absolute
   paths.** Root cause: `DatabaseProvisioningProbe::fromEnvFile()` read `.env`
   with `parse_ini_file`, whose dialect differs from the runtime's phpdotenv —
   the hand-added demo section comment (`# --- Disposable demo (GET
   /demo/standard, ...) ---`, note the `#` and parentheses) is a parse error
   there. Warnings printed before headers broke `refuse_install()`'s 403 and
   neutralized the DB-probe guard layer (marker layer still held). Fix: parse
   with `Dotenv::parse()` (same dialect as `ConfigLoader`), degrade unreadable
   `.env` to an EMPTY env silently — never partial, never output. Three
   regression tests incl. the live incident shape. The previously untested
   `fromEnvFile()` seam now has coverage. Cross-filed the same bug against
   vault (nene-vault#144; clear does not use `parse_ini_file`).

Findings:

- 🔴 **Audit CSV export 401 in production** (the one NG) → filed **#83**.
  `download-audit-csv.ts` claims to mirror the api client's auth headers but
  only sends `Authorization` — missing the `X-Authorization` mirror that
  client.ts sends because HETEML's front proxy strips `Authorization`
  (#67/#68). Verified the diagnosis live: same token, `Authorization`-only →
  401; with `X-Authorization` → 200 and a correct CSV
  (`timestamp,actor,action,deal_id,field,before,after`). Local dev can never
  reproduce this — the header only gets stripped in production.
- 🟡 **Amount yen⇄cents mismatch** (create 1,234,567 → header ¥12,346):
  already tracked as #80 with a fix branch in flight; noted, not re-filed.
- ⚪ Deleting a deal from its detail page triggers one benign
  `GET /api/v1/deals/:id` 404 refetch (console-only, no UI impact).
